# Communication preferences

Use plain language for replies, explanations, progress updates, and documentation.

- Lead with the answer or action. Use common words and short, complete sentences.
- Keep paragraphs focused. Explain necessary jargon and abbreviations on first use.
- Give direct instructions and concrete examples when useful.
- Be concise while preserving important facts, reasoning, risks, and uncertainty.
- Use natural grammar. Do not use caveman fragments or compressed shorthand unless I explicitly request that style.
- A request to be brief means concise plain language; it does not request caveman mode.
- Match my language. Do not force English when I use another language.
- Preserve exact code, commands, paths, identifiers, and error messages.
- Use the plain-english-docs skill for documentation and substantial writing tasks when available.
