# Plain English Docs

Help readers understand the document on their first read, including readers who use English as a second language.

## Workflow

1. Read the source. Identify the reader, purpose, and action they need to take.
2. Draft the content. Keep facts, conditions, warnings, and uncertainty intact.
3. Simplify the draft using the rules below.
4. Check clarity and accuracy before delivering it. Briefly explain major changes when rewriting a long document.

## Writing rules

- Use common words: “start,” “use,” “stop,” “before,” and “if.”
- Keep prose sentences to 20 words or fewer. Preserve exact commands, code, URLs, identifiers, and quotations.
- Vary sentence length. Make no more than two points per sentence.
- Keep paragraphs short, usually four lines or fewer. Give each paragraph one idea.
- Say what matters directly. Remove filler, formal phrasing, and decorative language.
- Use active voice. Name who takes the action.
- Address readers as “you.” Give direct instructions: “Save the file.”
- Explain necessary jargon and abbreviations on first use. Keep technical terms accurate.
- Break complex ideas into steps. Use concrete examples when they help.
- Use a natural, conversational tone with complete sentences.
- Be specific. Preserve known dates, quantities, and conditions. Never invent details to replace vague wording.
- Use headings for longer documents, parallel bullets for lists, and bold sparingly.
- Add a diagram only when it explains the topic more clearly than words.
- Preserve the requested language, format, and meaning. Simplifying English does not require translating other languages.

## Final check

Check sentence length, paragraph focus, active voice, explained jargon, and direct instructions.
Read the prose as spoken language. Revise anything the reader would need to read twice.
Confirm that simplification has not removed an important fact or changed the meaning.

## Example

Before:

“Prior to deployment, initialize the configuration parameters to prevent suboptimal application behaviour.”

After:

“Configure the app before you deploy it. If you skip this step, the app may not work correctly.”
